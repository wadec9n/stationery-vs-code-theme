# Stationery

> [!NOTE]
> This theme is a work in progress. Please file an Issue for any problems you encounter.

Stationery is a VS Code theme for people who take notes on paper. It comes in dark and light variants.

## The themes

### Stationery Light

A clean white editor with the surrounding chrome — sidebar, tabs, panels, status bar — shifted a half-step warmer into soft parchment. Text is nearly black. Syntax falls into:

- Deep terracotta for keywords and control flow.
- Forest green for strings (including JSX/Astro attribute values).
- Muted blue for types, classes, and HTML tags.
- A slightly brighter blue-teal for functions and methods.
- Warm ochre for properties, JSX attributes, and JSON keys.
- Rust for numbers, booleans, and regex.

### Stationery Dark

A near-black editor with charcoal chrome and warm cream text. The accents lift to hold weight against the dark field:

- Bright apricot for keywords and control flow.
- Soft mint for strings (including JSX/Astro attribute values).
- Pale cyan-blue for types, classes, and HTML tags.
- A brighter sky blue for functions and methods.
- Warm gold for properties, JSX attributes, and JSON keys.
- Desaturated terracotta-rust for numbers, booleans, and regex.

## Development Process

This theme was developed following [the excellent guidance that Sarah Drasner provided](https://css-tricks.com/creating-a-vs-code-theme/) while developing the [Night Owl theme](https://github.com/sdras/night-owl-vscode-theme). Night Owl has long been my theme of choice.

Claude and Codex were used heavily to create this theme. Building it was partly an exercise in shipping a usable project through agent and skill workflows that made iteration quick.

## Demo files

The `demos/` directory holds a compact but varied set of real-world files generated by Claude and Codex for theme evaluation: JavaScript, TypeScript, JSX, TSX, Astro, HTML, CSS, SCSS, Markdown, MDX, SQL, shell, Dockerfile, JSON, JSONC, YAML, TOML, plus a broader set of backend languages including Python, PHP, Go, Java, C#, Rust, Ruby, and C++.

### How they were generated

The files were written from scratch by Claude with a single goal: pack as much token variety as possible into a small, realistic file. Each one is shaped to exercise the syntax features that tend to expose weaknesses in a palette — comments (single-line, block, doc), strings (plain, template, interpolated, heredoc), numbers, keywords and control flow, operators, types and generics, decorators/annotations/attributes, regex, and any language-specific flourishes. None of the files are copied from other repositories.

The fixtures are intentionally self-contained so they open cleanly without repo-local components, assets, or a demo toolchain. They are still meant to feel like plausible code rather than nonsense that happens to colour nicely.

### How to use them

When iterating on the theme, open the demos side-by-side and look for problems the eye picks up faster than a token map will:

1. Install or reload the theme, then open the `demos/` folder in VS Code.
2. Switch between Stationery Light and Stationery Dark via **Preferences: Color Theme**.
3. Walk through each file and check for:
   - Tokens that disappear into the background (insufficient contrast).
   - Tokens that shout louder than they should (keywords overpowering identifiers).
   - Inconsistent treatment of the same concept across languages — e.g. JSON keys vs. YAML keys vs. JSX attributes.
   - Comments that are too prominent or too faint to scan past.
   - Invalid syntax, diffs, and diagnostics that should stand out without overwhelming the page.
4. Use **Developer: Inspect Editor Tokens and Scopes** (from the command palette) on any token that looks off, then adjust the matching rule in `themes/stationery-dark.json` or `themes/stationery-light.json`.

Adding a new file type? Keep it self-contained, representative, and dense with the syntax features that matter. A small realistic fixture is more useful than a large synthetic one.
